# EV3 / AM1808 emulation boundary

LEGO MINDSTORMS EV3 uses a TI AM1808 with an ARM926EJ-S (ARMv5TEJ), not a
Cortex-M device. The public source of truth for the memory map and AINTC is
TI's [AM1808/AM1810 Technical Reference Manual, SPRUH82C][trm]; the public
Linux board description is `da850-lego-ev3.dts`.

The first executable Renode boundary in this fork is deliberately narrow:

- exact ARM926 CPU type and AM1808 SRAM/64 MiB DDR addresses;
- exact `0xFFFEE000` DA8xx AINTC with 101 events, IRQ/FIQ routing, indexed and
  bitmap enable/status/acknowledge registers, channel maps and vectors;
- the three AM1808 16550-compatible UART addresses and event numbers;
- both DA8xx PSCs, both PLL controllers and SYSCFG0 at their exact AM1808
  addresses, including access masks and reset semantics;
- an explicit, public post-EEPROM handoff preset for the EV3 clock, power and
  pinmux values, selected by the platform instead of executing proprietary
  boot ROM or EEPROM contents;
- a source-built MIT smoke image proving reset, ARM execution, UART1 output,
  software-triggered event 53, IRQ exception entry and acknowledge;
- a second independently authored MIT image proving PSC state transitions,
  PLL divider GO transitions, revision-2.2 SYSCFG access and EV3 pinmux values;
- both EDMA3 channel controllers and all three transfer-controller register
  endpoints at exact AM1808 addresses, with completion/error routing to AINTC;
- an independently authored MIT EDMA image proving both a software-started
  memory copy and MMC/SD0 RX hardware event 16 through physical event 11;
- Renode's existing GDB server (`machine StartGdbServer <port>`) for register,
  memory, breakpoint, watchpoint and single-step debugging.

It does **not** use or redistribute recovery firmware. It is not yet a Linux
or full EV3 claim. Timer64 and the PSC/PLL/pinmux control boundary are modeled;
the remaining boot-critical work is MMC/SD, GPIO and LCDC, followed by
the EV3-specific SPI/ADC sensor and motor front ends. PRU is not on the Linux
boot critical path and should follow those peripherals.

## Post-EEPROM handoff contract

`platforms/cpus/am1808.repl` explicitly selects each control model's
`postBootloaderState` constructor preset. This is an emulation boundary, not a
claim that Renode ran the ROM or EEPROM loader. It sets PSC0 modules 6, 7 and
14 and PSC1 modules 6 and 31 enabled; PLLC0 to the EV3 300 MHz clock plan
(`PLLM=0x18`, pre-divider `/1`, post-divider `/2`, SYSCLK2 `/2`, SYSCLK6 `/1`);
and SYSCFG0 `PINMUX3=0x00001101`, `PINMUX4=0x22002210`,
`PINMUX10=0x00222222`, `SUSPSRC=0xf7d6ffff`. The modeled device reports
silicon revision 2.2, where SPRUH82C states KICK protection is disabled and
SYSCFG remains writable; both correct and incorrect KICK writes are inert.

The source-built `am1808-control-smoke.S` rejects a wrong preset, changes and
restores a PLL divider through `GOSET`, transitions PSC0 module 6 through
synchronous reset, exercises incorrect and documented KICK sequences while
independently mutating PINMUX, SUSPSRC and CFGCHIP registers, and restores the
handoff state. Only then does UART1 emit
`EV3 PSC PLL PINMUX OK`. Focused model tests separately cover cold-reset and
invalid-access behavior, so the board preset cannot hide those semantics.

## EDMA3 functional boundary

EDMA0 CC is mapped at `0x01c00000` (32 KiB) with completion/error on AINTC
events 11/12; its 1 KiB TC0 and TC1 endpoints are at `0x01c08000` and
`0x01c08400` with errors on events 13 and 32. EDMA1 CC is at `0x01e30000`
(32 KiB) with events 93/94, and its 1 KiB TC0 is at `0x01e38000` with error
event 95. Each CC is explicitly attached to its transfer controllers so a bus
fault is reported by the TC selected through DMAQNUM. These addresses and
event assignments follow SPRUH82C.

`am1808-edma-smoke.S` first grants region 0 access through DRAE0, then programs
the standard PaRAM and shadow registers. Its software build starts channel 0
through ESR. Its hardware build enables channel 16 after the isolated workflow
has pulsed the EDMA request input for the public MMC/SD0 receive mapping before CPU start; this
proves disabled-event latching and EESR drain behavior. Both copy a deliberately
non-matching 16-byte buffer, require the EDMA0 completion GPIO to arrive as
physical AINTC event 11, clear IPR through ICR in the ARM IRQ handler, and
compare every destination word before emitting success. Missing completion,
the wrong pending bit, and data corruption have distinct UART failure output.
The injected line proves the documented channel mapping, not MMC integration;
the MMC/SD controller remains a later checkpoint.

Transfers currently complete immediately and deterministically. This is a
functional programming/bus/interrupt model, not a cycle-accurate model of TC
queue latency, FIFO occupancy or interconnect arbitration.

## Other permissive ARM9 projects

These are useful validation inputs, not replacements for the AM1808 SoC model:

| Project | License / use | Decision |
|---|---|---|
| [FreeRTOS-GCC-ARM926ejs at `aa1507f`][freertos] | Source headers and README state MIT; ARM926 on VersatilePB | Adapt only as a second source-built RTOS payload after replacing its board startup, interrupt controller and linker map. Do not treat VersatilePB success as EV3 support. |
| [nfsu/armulator at `39afe23`][armulator] | MIT, basic ARM7/ARM9TDMI interpreter | Useful instruction/exception differential oracle, but lacks ARM926EJ-S MMU and AM1808 peripherals. |
| [archshift/llama at `380326d`][llama] | BSD-3-Clause ARM9 interpreter with GDB stub | Use its instruction, exception, breakpoint and single-step behavior only as a differential oracle; Renode already supplies the product GDB server and AM1808 bus. |
| [Orkie/petraea at `6e602e6`][petraea] | MIT ARM9 JIT and tests | Use its instruction tests as a second differential oracle; it is not an AM1808 SoC implementation. |
| [risclite ARM9-compatible soft core at `fc17416`][risclite] | Apache-2.0, synthesizable ARMv4-class Verilog | Reject for the product path: it is not ARM926EJ-S, and a Verilator integration would add complexity without modeling AM1808. |
| [OpenNuvoton MPU-Family at `18aa8bf`][nuvoton] | ARM9/Cortex-A35 resource index; GitHub detects no repository-level license | Reference its public board/BSP links only. It targets different SoCs, and each linked component requires its own provenance review. |

Renode remains the implementation engine because its ARM926 translation core,
system bus, analyzers, record/replay and GDB integration let us add the missing
TI/EV3 devices without creating a second debugger and scheduler.

## Hosted throughput qualification

The source-built active-loop smoke workload passed the unpaced 300 MHz target
on a GitHub-hosted Ubuntu 24.04 runner on 2026-09-28. After one 300-million
instruction warm-up, all five measured passes retired exactly 300 million guest
instructions. Median throughput was **408.22 MIPS (1.361x)**; the observed range
was **362.14–414.25 MIPS (1.207–1.381x)**. UART output and AINTC IRQ handling
were verified in the same process. The [workflow run][throughput-run] retains
the JSON receipt as its `ev3-arm9-throughput` artifact.

The harness sets `SetGlobalAdvanceImmediately true`, so this is execution
throughput rather than Renode's default wall-clock pacing. The payload uses an
ADD/EOR/SUB/CMP/BNE loop because Renode correctly recognizes a branch-to-self
as idle and then advances virtual time without retiring guest instructions.
Reproduce after a source build with:

```sh
tests/platforms/LEGO_EV3/am1808-throughput-test.sh \
  output/bin/Release/Renode.dll /tmp/ev3-arm9-throughput.json
```

This qualifies a hot CPU-bound ARM926 translation path, not Linux boot or the
missing EV3 peripherals. Results will vary with the host and runner load; the
five-pass minimum above, not a single best pass, is the useful safety margin.
